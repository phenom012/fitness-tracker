## 0. 결론 (Executive Summary)

| 구분 | 결론 |
|---|---|
| 복귀 전략 | **시간표가 아니라 '게이트(통과 조건)'로 복귀한다.** 날짜는 최소 기간일 뿐, 통과 못 하면 단계 유지. |
| 현재 병목 | **수평 밀기(벤치·푸시업)에서만 어깨 앞쪽 통증 재현** + 우측 무릎 이상감. 당기기·스캡션·하체 힌지는 허용. |
| 앱의 문제 | 현재 앱은 "무게·세트 기록기"다. 그런데 복귀의 의사결정 변수는 **무게가 아니라 증상 반응(운동 중/직후/밤/다음날 아침)** 이다. 핵심 데이터가 앱에 없다. |
| 앱 개편 방향 | 기록기 → **복귀 운영 시스템**: ① 오늘 세션 자동 로드 ② 4시점 증상 로그 + 신호등 판정 ③ 게이트 대시보드 ④ 체성분 추적 |
| 목표 시점 | 6개월 후 (2027-04) — 체지방 14~16%, 골격근 33~34kg, 어깨 통증 0~2 상태로 Rx 가능 범위 복귀 |

### 1-3. 최근 반응 패턴 (10/7, 10/12 기록)

- 벤치 30kg×5세트·푸시업 10회 → **우측 앞쪽 어깨 통증 재현, 푸시업 직후 팔 떨림**
- 밴드 턱걸이 5×6, 시티드 로우 60kg×5, 스캡션 3kg×6 → **통증 특이반응 없음**
- 운동 후 통증이 줄고 다음날 악화 없음 → **'적절한 부하는 사용 가능'** 신호
- 오버헤드 스트레칭(팔꿈치 머리 위)에서 통증 재현 → 강한 오버헤드 스트레칭 제외
- 9/17 AMRAP에서 월워크 수행 기록이 있으나 10/13 플랜은 월워크 보류 → **문서 간 불일치 (아래 §5 참조)**

## 2. 복귀 로드맵 — 게이트 방식

> Notion 플랜의 레벨을 따라 **Physical Capacity → Sport-specific Capacity → Return to Sport → Return to Performance**.
> 날짜는 *최소* 기간. 게이트 미통과 시 같은 단계 연장. 통증 3/10 이상이면 직전 단계 복귀(기존 규칙 유지).

| Phase | 최소 기간 | 수업 빈도 | 핵심 과제 | **통과 게이트** |
|---|---|---|---|---|
| **P0 재진입** | 10/13~11/9 (4주) | 화·목 2회 | 수업 참여 습관 복구, 모든 밀기는 인클라인/스케일, 무릎 반응 확인 | 8회 중 7회 이상 참석 · 수업 다음날 아침 통증 ≤2 (8회 중 7회 이상) · 인클라인 푸시업 3×10 (2~3초 정지) 통증 0~2 · 무릎 붓기/걸림 없음 |
| **P1 기초 용량** | 11/10~12/7 (4주) | 화·목 (+선택 토) | **바닥 푸시업 3×10 무통증** 복구, 스트릭트 풀업 3×5, 빈봉 스트릭트 프레스 3×10(템포 3-1-3) 2주 무통증 | 위 3개 연속 2세션 통과 |
| **P2 종목 특이 용량** | 12/8~1/18 (6주) | 주 3회 | 오버헤드 20→30kg (2주마다 +5kg), 랜드마인 프레스 병행, 로잉·바이크 엔진 빌드, 러닝 복귀 | 오버헤드 30kg 3×5 무통증 4주 · 스트릭트 풀업 5회 |
| **P3 복귀 (RTS)** | 1/19~3/1 (6주) | 주 3~4회 | 월워크 스케일→풀, 킵핑 풀업(주 2회 상한·48h 회복), WOD Rx 확대 | 빈봉 OH 15회 무통증 4주 유지 후 월워크 · 풀업 5회 무통증 후 킵핑 |
| **P4 퍼포먼스** | 3/2~4/13 | 주 4회 | 벌크업 마무리, 체성분 목표 판정, 스내치·머슬업은 *재평가 결과에 따라* | 6개월 목표 달성 판정 |

**상시 규칙 (기존 플랜 그대로 시스템화)**

| 증상 반응 | 판정 | 조치 |
|---|---|---|
| 중 ≤2 · 직후 악화 없음 · 다음날 아침 악화 없음 | 🟢 | 유지 또는 소폭 진행 |
| 3~4 또는 다음날 뚜렷 악화 | 🟡 | 해당 동작 중량·ROM·볼륨 ↓ |
| ≥5, 날카로운 찝힘, 팔 저림/감각저하/근력저하/반복 떨림 | 🔴 | 해당 동작 중단 · 저림·근력저하는 **경추 신경학적 평가 분리** |

**병행 과제 (앱 밖)**
1. 과거 MRI/초음파 판독지 확보 → "20% 파열" 정확한 위치·크기 확인 (현재 기억 기반 정보)
2. 10/7 푸시업 후 팔 떨림 재현 시 정형외과/재활의학과 재평가 (진행성 신경 증상 배제)
3. 영양: 단백질 목표 설정(체중 81kg × 1.6~2.0g ≈ 130~160g/일), 수면 기록

## 3. 앱 개편 기획

### 3-1. 문제 정의

| 현재 앱 (`index.html`, 단일 파일) | 복귀에 필요한 것 |
|---|---|
| 종목·세트·**lbs** 기록 | **kg 단위** (Notion은 kg 사용) |
| 통증 입력 없음 (WOD RPE만) | **어깨/목/무릎 × 4시점(중·직후·밤·다음날 아침)** |
| 요일 개념 없음 | **고정 주간 스케줄 자동 로드 + 체크리스트** |
| PR 중심 통계 | **게이트 통과 현황 + 증상 추세 + 출석률** |
| 클립보드 복사만 | **Notion 일지 포맷 내보내기 + JSON 백업** |
| 체성분 없음 | 인바디 기록 + 목표 대비 진행률 |

### 3-2. 기능 우선순위

| 우선순위 | 기능 | 설명 | 완료 기준 |
|---|---|---|---|
| **P0** | 오늘 탭 | 요일별 세션(월/금 재활, 화/목 수업, 수 회복, 토/일 휴식)을 자동 로드 → 항목별 체크 + kg/횟수 기록 | 앱 열면 오늘 할 일이 바로 보임 |
| **P0** | 증상 4시점 로그 | 부위(어깨·목·무릎)별 0~10: 운동 중 최대 / 직후 / 밤 / 다음날 아침. 다음날 아침 미입력 시 홈에 알림 배지 | 세션당 입력 ≤30초 |
| **P0** | 신호등 판정 | §2 규칙으로 🟢🟡🔴 자동 산출 + "다음 세션 권고(유지/감량/중단)" 문구 | 규칙 단위테스트 가능한 순수 함수 |
| **P0** | 단위 kg 전환 | 기존 localStorage(v1) 데이터는 lbs→kg 변환 마이그레이션 | 기존 기록 보존 |
| **P1** | 게이트 대시보드 | 푸시업/풀업/빈봉 OHP/월워크 등 게이트별 "연속 무통증 세션 수" 진행바, 현재 Phase 표시, 동작 허용표(Rx/스케일/보류/금지) | 게이트 조건 편집 가능 |
| **P1** | 수업 WOD 기록 개선 | 동작별 스케일링, 보류 동작 사용 시 경고, 수업 출석 스트릭 | 화·목 출석률 표시 |
| **P1** | 체성분 탭 | 체중/체지방/골격근/허리 입력 → 목표선과 비교 | 월 1회 입력 기준 |
| **P2** | 주간 리뷰 | 출석, 당기기:밀기 볼륨비, 증상 추세, 다음 주 권고 자동 요약 | 일요일 자동 생성 |
| **P2** | 내보내기 | Notion `운동 일지` 포맷 Markdown 복사 + JSON 백업/복원 + (선택) 생활변수(수면 자세, 앉은 시간) | 복원 시 데이터 동일 |

### 3-3. 데이터 모델 (v2)

```
state = {
  version: 2,
  settings: { phase: 'P0', unit: 'kg', schedule: {...} },
  sessions: [{ id, date, type: 'rehab|class|recovery|rest',
               items: [{ name, sets:[{kg, reps}], done, note }],

  symptoms: [{ sessionId, region: 'shoulder|neck|knee',
               during, post, night, nextMorning, note }],
  gates:   { pushupFloor: {streak, passedAt}, strictPullup: {...}, ... },
  body:    [{ date, weight, bodyFatPct, smm, waist }],
  wods:    [...기존 구조 + movements[]]

```

### 3-4. 기술 방침

- **단일 `index.html` 유지** (GitHub Pages + 홈화면 추가). 빌드 도구 도입 안 함.
- `localStorage`는 기기 변경·삭제에 취약 → **JSON 내보내기/가져오기를 P0 보조로 포함** (진행 중 데이터 유실 방지).
- Notion 직접 동기화는 정적 페이지에서 토큰 노출 위험 → **앱은 Notion 포맷 텍스트 생성까지만**, 주간 Notion 반영은 Claude(Notion 연동)가 대행.
- 신호등/게이트 판정 로직은 UI와 분리된 순수 함수로 작성해 검증 가능하게.
